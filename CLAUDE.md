# kb: how this code is shaped

Read before changing anything under `src/kb/`. These are rules, not preferences;
a change that breaks one is refactored into place first, then made.

## Module map

| module | owns | never holds |
|---|---|---|
| `contract/` | `kb.proto` and generated code | hand-written logic |
| `servicer.py` | the rpc adapter: each rpc a request in, one call into the domain, a response out, or, for `Export`, the stream of them, inside `boundary.py`'s one wrapper; which rpcs write (`writes`, marked by `changing`), asked of each request, a set of creates or of replacements writing unless its request asks that it be checked only (`changes.checked_only`), which is then checked (`write.checked`) and not landed | domain logic, file paths, git |
| `boundary.py` | the one fail-closed wrapper: the store opened for a call and closed when it ends (unless the call starts one), its reads held at one moment, one call into the domain, the response it gave, or the call's refusal, or the fault of any exception that escapes, with nothing written; the client's clock read so that its failure is `ClockFailed` (`guarded`); a call that writes refused while a server owns the store (`served.py`), unless the servicer is the one that server hosts, whether it writes asked of its request by what its rpc is marked with (`writes`; `never` for one that only reads); and the same wrapper for an rpc that answers with a stream and only reads (`streamed`): the store and its one read moment kept open until the stream ends, its caller closes it or lets it go, or it fails, each thing the call gives a message as it is asked for, and a refusal or the fault of any exception that escapes one more message, the stream's only one when nothing was given and its last otherwise; no message given from inside the guarded block, so an exception the caller throws into the stream is raised to it as itself and a stream it closes or lets go ends with no further message, the store let go first, on whatever thread it reads, closes or lets go (the store opened for it held to no thread) | domain logic, the rpcs, file paths, git |
| `escapes.py` | the fault an exception escaping the domain becomes inside `boundary.py`'s one wrapper: the clock's failure (`ClockFailed`), `Busy`, an earlier or a later kb's store, a database that cannot be read, anything else | catching exceptions, messages (`refusals.py` makes each fault from plain values) |
| `responses.py` | an rpc's or an operator's command's response made from what its call gave, or from the faults it was refused for: an rpc's result or refusal, never both; an operator's command's, or `kb.init`'s, faults; a change's result and a set's, made from what the set landed, or, checked only, would land, its name then empty; each message of an export's stream, a file or the end with its position, made from what the export gave | domain logic, conversions, I/O |
| `starting.py` | `kb.init`, a store started in the client's own process, off the wire, which the operator's `kb init` calls too: who starts it and where, converted, then one call into the domain inside `boundary.py`'s one wrapper; `kb.NotStarted`, raised with the faults when it refuses; `kb` publishes both; and the faults it would refuse a root for, asked before anything is made (`refused`); a step a start takes on the filesystem first, inside that wrapper (`prepared`) | domain logic, finding a store, rpcs |
| `operating.py` | the operator's commands that are not rpcs (export, the import check, the import, the backup, the restore), each one call into the domain inside `boundary.py`'s one wrapper, the restore over no store opened, the import refused while a server owns the store (`served.py`), as a change asked directly is | domain logic, finding the store |
| `values.py` | conversion of single request fields into validated values: an artifact's IRI, a kind (its type's IRI) and a type version's IRI, each of kb's grammar or refused with `locator`, the version of its type a change names (none for an empty name, `named`), locators, a locator's name read as an artifact's IRI or as a part's, the artifact's IRI, `#` and the part's place, as `names.linked` reads a link (`locator`), which names what the IRI with that place beside it names, a locator giving a place both ways refused with `locator`, and a name that reads as neither refused whole as a name, what a read names (an artifact's locator, or a type's with the version its name gives, `read`), a create's title, the revision a change says it read (0 for none), a path below a type as its segments (`Below`, converted by `below`: of `names.py`'s grammar or refused with `locator`); the one reading of a moment in UTC, "UTC unless it says otherwise", which `in_utc` provides for both `since` and the clock | anything that touches the store or the filesystem |
| `roots.py` | the values a store's start and the operator's commands take: a root, the directory an export is written to or an import read from, the file a backup is written to or restored from, each as the name given and the path it makes; what stands there is for the store, the export, the import or the backup to check | anything that touches the store or the filesystem |
| `content_values.py` | conversion of the content a request carries into a value (`Content`, its tree and every problem found, said of whichever artifact it turns out to be for): a whole artifact's content, read as canonical text holding only what its type declares, with the identity keys that travel beside it refused (`content`), a node's (`content` not at the root), and an item's, with no name of its own and its title read as text (`item`); a content that cannot be read is a problem of the rule `content`, never an exception. It is not `content.py`, which only moves canonical text to a value and back, and holds no faults | anything that touches the store or the filesystem, a single field's conversion (`values.py`) |
| `signatures.py` | who makes a change and why: the actor, the signature, and the conversions of a writer's and a reader's `Signature` and a starter's role and piece of work; refuses one that does not sign | I/O, other request values |
| `requests.py` | each rpc's request but the changes as the values its one domain call takes, built from `values.py`, a read's with the version of a type it names when it names one, a list's with its kind, taken when one is given or no path is (so a list by neither is refused for its kind), and its path below the type, a follow's with its path below the type, an export's with the kind and the path below the type it is narrowed to, each when given (`Selection`); refuses a request that does not convert, with every fault when more than one field fails | domain logic, I/O, what an IRI looks like (`names.py`, through `values.py`) |
| `changes.py` | each change's request, alone or in a set of one kind (`BatchCreate`, `BatchReplace`, `BatchAdd`, `BatchRemove`), as the values its one domain call takes, built from `values.py` and `signatures.py`; refuses a request that does not convert, an empty set, and a set two of whose creates carry one IRI (on each create after the first, once, beside every other fault of the set, whether or not either create converts), each change of a set that does not convert standing in its place as its refusal; the version of its type a replacement names, alone or in a set, as `values.py` reads it; whether a set of creates or of replacements asks to be checked only (`checked_only`) | domain logic, I/O |
| `names.py` | kb's IRI grammar (`iri`), an IRI split into its host and segments (`split`), the IRIs an IRI sits under, by whole segments and nearest first, never the IRI itself (`above`), an IRI's path below a type's IRI (`below`) and whether a path below the type selects an IRI of a type, by whole segments (`selects`), the grammar of a path below a type, segments of the IRI's grammar joined by single slashes, read as its segments (`path`), a type version's IRI written and read (`versioned`, `version`), and the IRI of the type that describes types (`TYPES`); the grammar of a plain name (`plain`); how a link's place inside an artifact, a link into a part of one (`pointing`, `linked`) and a type version's `kb:` reference are written and read; the export layout's place for an artifact, a type's at its version (`place`), that place written as one path (`placing`), and the IRI and version a file's place gives (`filed`); the one order IRIs are given in (`order`) | item names, I/O |
| `validation.py` | the composed effective schema, the 2020-12 metaschemas it resolves through, and the checks JSON Schema cannot express, among them whether a link lands: on a held artifact, or part of one, of a kind its field allows, or on an IRI not held under a held type the field allows (`composition.nearest_type`), the part it names there not checked; and the one judgement of a link that already waits (decision/a-link-that-waits-keeps-waiting): one that does not land is no fault when it is among the links the store held for its artifact landing on nothing held (`waited`, given by `draft.py` for a change and by `check.py` for the store), told as `port.told` tells it (the same field of the same thing, the artifact or the item of that name, the same IRI and part, wherever it stands in a list), and fails only for the part, its target held, of an allowed kind, and lacking it; a link an import brings (`imported`, said by `drafting.py` for an import's change and by `examining.py` for a file) judged so whatever the store held, so it waits too; the links that neither land nor wait given by themselves (`unlanded`), for a corpus that is where they would land | file access |
| `check.py` | the check of the whole store, read through the port: every artifact against the version of its type it conforms to, each artifact's violations in order (`fault_order.py`), the stale listed beside the violations, the placeholders listed apart as `query.py` gives them, a link into a part the artifact held at its IRI lacks listed there and left out of the violations by `validation.py`'s judgement of a link that already waits, which it hands each artifact's waiting links, each as `port.told` gives it, so a fault for anything else there is reported | checks of its own, writes |
| `composition.py` | a type read through what it is built on: its composition, base first, what the item type at the end of a walk through collections declares (`declared_at`), the type version a `kb:` reference names, held and read as that version was made whichever version its type stands at, every type's schema and kind's schema read through the version the corpus keeps (`kept`, `current`; a version kept is not proof its type is held, which is asked of the type's own row), and the types an artifact of a kind is read through, given the version of its type it is read through, each `kb:` reference followed at the version it names (`read_through`); the other types any held version of which reads a version of a given type, by a `kb:` reference to a shape or by being built on it, each once (`readers`); the nearest held type an IRI sits under (`nearest_type`), and whether an IRI belonged to a type the corpus no longer holds, no nearer held type standing between them (`nearest_was`); the version of a type a create names, whatever its type stands at, refused with `version` when the store does not hold that version (`version_schema`), the version an artifact conforms to, as it names it (`conforming`) and as the corpus keeps it (`conformed`), and whether an artifact may move to a version, one kept, of its own type and not earlier than its own (`moves_to`); the kind an artifact is of, as its type version names it; an artifact's schema, the version it conforms to (`artifact_schema`), and the version a kind's type stands at, which the check of the store measures the stale against (`kind_schema`) | checks, file access |
| `links.py` | the one reading of links: every link an artifact carries, wherever it sits, and those links as the port takes them, read through the type given, always the version of its type the artifact conforms to, whatever its type stands at, each saying the held type its target's IRI sits under (`composition.nearest_type`), whether or not the target is held, since it may be removed before the link lands, what holds it by name (`holder`: the artifact itself, or the item by its name, an item with no name by where it stands), and whether it is among the links it is given as those the store held waiting for the artifact (`port.Link.waits`), never the implicit one; what tells each carried link from every other, as the port tells the link handed (`told`) | checks, store access |
| `definitions.py` | a type checked as it is written: the version of a type each `kb:` reference names is held, it is not built on itself, kb's keywords stand only where kb reads them (`keywords.py`), each link field kb reads states its whole shape | file access, checking artifacts against a type |
| `keywords.py` | where kb reads its keywords in a type, and every place one of them stands | checks, faults or file access |
| `fault_order.py` | the order an artifact's faults are given in: its places as it reads back (`settled.py`'s order), a place before what is inside it, then at one place by the names of the rules broken; used by `drafting.py` for each change and by `check.py` for each artifact | making or checking faults |
| `refusals.py` | the faults the domain makes of what a store holds (but a type as it is written) and of a type version it does not hold, of a version a replacement names that its artifact cannot move to (`not_later`), of a create's IRI (one that does not sit under its type's, `not_under`, one already held, `already_held`, one two creates of a set carry, `carried_twice`; a type's under which an IRI belongs to another type, `belongs`), of a name a create gives a part (`misnamed_part`, worded apart from a change's `misnamed`), of a store that cannot be read, and of a store or server that cannot be reached (`served`, `connection`, `unreachable`), each with its rule and message, from plain values | conversions, type checks, exceptions, the operator's directories and files |
| `file_refusals.py` | the faults of the operator's directories and files, each with its rule and message, from plain values: a directory an export or an import is refused for, a place a backup cannot be written at, a file offered for restore that is not a backup this kb can read, a file offered for import that cannot be read, is not in canonical form, is of a kind nothing offers a type for, conforms to a version of its type nothing offers (rule `version`) or differs from what the store holds at its IRI (rule `differs`), and an import refused whole, for its check's errors or for each IRI at which it differs | conversions, checks, exceptions |
| `type_refusals.py` | the faults of a type as it is written, each with its rule and message, from plain values: a shape no held version of a type has, a type built on itself, a keyword of kb's where kb does not read it, a link field that leaves out part of its shape or says what kb does not know | conversions, the checks that find them, exceptions |
| `rules.py` | the name of every rule a fault of kb's own carries, which kb publishes (decision/published-contract-v2) | faults, messages |
| `write.py` | the write pipeline: the set drafted (`drafting.py`), each entry's stamp settled, then the set and its entries landed through the port in one call; when the port finds an artifact it changes or a type it was read through has moved or been removed since, or something landed at an IRI the set was drafted over as holding nothing (`standing.py`), drafted, stamped and landed again inside the port's `exclusive` block, which nothing else lands during, so a change that says the revision it read is compared again there and refused if its artifact moved, and one a type defined since stands nearer to is refused there as its draft finds it; a set its draft says lands only as drafted inside that block (`drafting.py`'s `Drafted.locked`) never landed as first drafted; starting a store, the type of types handed with its first version, recording a snapshot; a set checked only (`checked`): drafted the same way against the store at one read moment and answered as it would land with no name, no clock read, no id minted, no write lock taken and nothing handed to the port | rpc types, SQL, checks of a draft |
| `drafting.py` | a set drafted against the store as it stands: every operation applied, every change checked against the state the whole set leaves, but that a link the store held waiting for its artifact before the set still waits (`draft.waited`, judged by `validation.py`, said on the link handed), and that each link an import brings into a part its held target lacks waits, each change, its content and the links it hands over, against the version of its type its artifact conforms to as the change left it (the one a create or a replacement names, the one an import's file names, else the one it conformed to), whatever its type stands at, every change the set makes to a type, each making a version that is kept, checked as a type (`definitions.py`), an import keeping the revision and type version its file gives, the imports a set makes of one type's versions put in the order of their numbers, in the places the set gave them, whatever order it gave them in, and handed one after another, each as that version, read at the revision the one before it left the type at (for the first, the revision the store's type stands at when it is a version above the one that type stands at, else 0), so the type stands at the highest; a type's removal refused with what `standing.py` finds in its way (`standing.in_the_way`); a set with no other fault refused, for a landing and for a set checked only alike, with every link into a part the store held in an artifact and a change of the set drops (`draft.dropped`), from an artifact the set leaves as it is (one the set changes or removes is judged as the set leaves it), the artifacts in the order the set first changes them and the links into each in the order of the names of the artifacts holding them, as the port's own check of a landing, which stays behind it, names them; whether the set lands only as drafted while the write lock is held (`Drafted.locked`), the port comparing nothing that would show what landed since: one that removes a type (a type made that reads it, a link landed that waits under it), one that defines a type (an artifact or a link landed under its IRI), one `standing.py` finds below an artifact a type could take the place of; each change's faults put in order (`fault_order.py`); each change then as the port takes it (`handing.py`), the IRIs `standing.py` hands as holding nothing; only what the set changes is handed, a type's change restating the links of no artifact | rpc types, writes, SQL |
| `handing.py` | each change of a drafted set as the port takes it: the type it is checked against (`typed`: the version its artifact conforms to as the change left it, whatever its type stands at), its entries in the order that type declares, recording that version, the last change to an artifact put in the draft so (`versioned`, an import keeping the version its file names), its canonical text, refused if it cannot be written (`serialised`), and the change handed (`handed`) read at the revision given, with the revisions of the types the version it was checked against is read through, and, for every change that leaves a type, of the types the version it makes refers to or is built on (so that one of them moved or removed before the landing has the set drafted again), the rows it is found by and, for a type, the version it makes; for the last change to an artifact, its links and the places of its parts, each link an import's change brings but the implicit one carrying the import's mark (`port_values.Link.imported`), which no other change's link carries | the draft's operations, checks, rpc types, writes |
| `edits.py` | what each operation of a set does to the draft, acting on the draft as the operations before it left it: what it names, a create's identity and the naming of its items (`naming.py`), the faults of the names it gives them carried with what it did as a change's are, an added item refused for a name inside it standing as a change that names no item, the store having given it none, the revision a change says it read against the one its artifact stands at, the revisions it makes, the version of its type its artifact ends at (the one it conforms to, kept by every change naming none, or the one a replacement names, refused with `version` unless the artifact may move to it, `composition.py`), a create's entries ordered as the version it names declares; an import's artifact put as its file gives it but for its items, named, and its entries, ordered (`naming.imported`), the faults of the names its file gives carried as a change's are, conforming to the version of its type its file names, which the draft must hold; never what its content or links come to, which `drafting.py` checks for every change against the state the whole set leaves | rpc types, writes |
| `item_names.py` | the names of items: the name a title gives (`title`, `slug`), the numbering that keeps a name free against those taken (`numbered`), the names the items of an artifact's collections are given, a name an item carries, from its create or from the store before, kept and taken before any is made (`items`), the names a create gives its items that an item may not carry, one that is not a plain name (text of `names.py`'s grammar, so never a name that is not text) and one two items of a collection carry, in every collection at every depth (`given`), and the names a revision hands back that the store could not have given, those and one no item of its collection had, the collection inside an item read against that item as it was held, in every collection at every depth too (`handed_back`), each with where it is and why (`Misnamed`); a plain name is `names.py`'s grammar | I/O |
| `naming.py` | what names a create's artifact and the items of what an operation puts in the draft: a create's IRI belonging to the type it names (the nearest held type it sits under, `composition.py`; a type's own is free but for what already sits under it and belongs to another type, `standing.py`, each such IRI refused with `belongs`) and held by nothing, a create carried twice in its set said once as the set's; the items of a new artifact named, those its create names keeping their names and the names it gives that an item may not carry refused with `misnamed_part`, and of a revised one named with those it held kept and the names it handed back, in a collection at any depth, refused with `misnamed`, each through `item_names.py`, which decides what an item's name looks like and whether it is free; an artifact an import brings as it would land (`imported`): its items named as a create names them, those its file names keeping their names, its entries in the order the version of its type it conforms to declares, with the faults of the names its file gives; the faults of the place an artifact a file brings stands at (`placed`), held to it as a create's IRI is but for what the draft holds there, which is the file's own; a type's content given the number of the version its define or change makes (1, then the next after the last, `draft.py`'s count), over any number its client sent | what an operation does, checks of content, writes |
| `draft.py` | the store as a set's changes would leave it, read like the store: what it holds, each artifact, a type's version (the type the draft put when it stands at that version or as the draft made it at that version before, any other as the store keeps it, a type's kept as first read; a type removed and put again holding only what was made since), the numbers of the versions of a type it leaves held (`versions`), the artifacts of a kind it holds (`ids`), the number a type's next version is made at, the set's own earlier versions counted, the links into one, those of what the set put read through the version each conforms to (one whose version the draft does not keep carrying none) and the store's standing for everything else, and the links to IRIs it does not hold, read the same way (`waiting`), over the port; the links the store held for an artifact, before the draft, that landed on nothing held, each as `port.told` gives it, read once for each artifact (`waited`); the places of the parts the store held in an artifact, before the draft, that the draft leaves it without (`dropped`); whether it put or removed what stands at an IRI (`changed`); each type as first read, and the revision it was read at | writes, checks |
| `standing.py` | what a type's place is settled by (decision/a-types-place-is-settled-by-what-sits-under-it): for an IRI a type would be defined at, the nearest held type above it and every IRI under the new type's that belongs to that other type, the artifacts of its kind held there (none under the type of types, to which no type belongs by where it sits) the IRIs not held that links wait on there with no nearer held type above, and the new type's own IRI when a link waits on it (not under the type of types, where the type defined is the artifact waited on), once each in `names.py`'s order, read from the draft as the operations before the define left it (`under`); and a set's changes as the port takes them, each saying that nothing is held (revision 0, among what it was read through) at every IRI where a type defined before it lands would stand nearer to what it makes or links to: between a new artifact's IRI and its type's, and between the target of each link it hands, held or not, and the type that target was found under, but an IRI the set itself changes; and whether the draft holds something at one of them, an artifact a type could take the place of at the same revision, which is handed for none (`guarded`); what stands in the way of a type's removal as the set leaves the store (`in_the_way`): each type a held version of which reads it (`composition.readers`) and each artifact holding a link to an IRI not held whose nearest held type it was (`draft.waiting`, `composition.nearest_was`), beside the artifacts of its kind, each once, in the order of their names; and whether a change removes a type (`removes_a_type`) or defines one (`defines_a_type`) | faults and messages (`refusals.py`), what an IRI sits under (`names.py`), writes, store access but through the draft |

| `query.py` | list (of a kind, or, by a path below the type, of every kind but the kind of types, which it tells the port to leave out: `left_out`, the one place that says which kinds a selection by a path with no kind leaves out, read by `export.py` too), follow (each step narrowed by a via, a kind and a path below the type, the path read below the type of what the step reaches, or, for an IRI not held, below the nearest held type it sits under, as `names.selects` matches it; the artifact followed from never narrowed), search, history, snapshot gathering, the placeholders (each IRI a link lands on nothing at, once, with every such link and the part it names, in the port's order), asked of the store through the port, the placeholders also made from waiting links handed to it, which `check.py` reads once (`placeholders_of`); a walk reaching an IRI the store does not hold gives it as `read.py`'s stub, marked as not held, of no kind, and does not walk on from it; a link into a part of an artifact reaches that artifact | writes, SQL |

## Rules that make whole classes of defect unreachable

1. **Fail-closed boundary.** Every rpc runs inside one wrapper in `boundary.py`
   that converts the request, runs the domain call, and turns any exception
   that still escapes into a fault with nothing written; an rpc that answers
   with a stream runs in it for the stream's length, a fault its last message. No other module
   catches broad exceptions.
2. **Parse, don't validate.** A request field becomes a validated value in
   `values.py` or `content_values.py` (its content) before anything else sees it. Domain and store functions take
   only those values, never a string that came from a request.
3. **A database that cannot be read is one fault.** A database that cannot
   be opened or read refuses every call and every command with one fault,
   rule `unreadable`, naming the database, and writes nothing; damage to
   files is found by the import check, not by the store.
4. **Draft, validate, land.** A set of operations applies to an in-memory
   draft, the whole draft validates, and only then is the set handed to the
   port, which lands every change with its history in one transaction or
   nothing. Nothing reads the store between handing the set over and its
   landing.
5. **One canonical checker**, applied to content after parsing and to bytes
   before writing. All YAML is 1.2.
6. **Names live in one place.** No module other than `names.py` and `item_names.py` decides what
   an artifact's or an item's name looks like or whether it is free;
   `journal.py` alone decides a journal entry's id.

## Size and shape

- No module over 250 lines; `servicer.py` under 150. When a change would
  cross a limit, split first.
- A function does one thing at one level of abstraction; if it needs a
  comment to separate its phases, it is two functions.
- Tests use the contract or the module's public functions, never private
  helpers.

## Working here

- `make dev` once; `make test` runs the suite in this checkout's virtualenv, in parallel (`-n auto`), the operator's commands run in-process (one test runs the installed `kb`); during red-green run the slice's marker for real results (`-m slice-N --runxfail`; without `--runxfail` a slice not built shows `xfailed`, exit 0), and the whole suite once per slice. A slice's whole-suite run for the record is made after `plan status N green`: before that the slice's own failing scenarios are still expected failures, and "0 failed" says nothing about them;
  `make contract` regenerates the stubs after `kb.proto` changes.
- The suite is green between slices: `make test` reports 0 failed, and a failure is a regression. A test carrying a
  `slice-<n>` marker (a scenario from its feature's `@slice-<n>` tag, a plain test from `slices.waits_on("<n>")`) is
  expected to fail while the living plan (`docs/superpowers/plans/2026-09-24-kb-slices.md`) lists slice n with a
  Status other than `green` (`tests/slices.py`): it still runs, its failure is counted as `xfailed` with the reason
  "slice <n> not built", and its passing before the plan says green as `xpassed`, never as a failure. A slice the plan
  no longer lists is built, and its tests run for real; a plan that cannot be read, or that gives a slice a Status
  the plan script does not know (the text before its first colon is `planned`, `in progress`, `green` or `blocked`),
  stops the run. While a slice is
  being built, `-m slice-N --runxfail` runs its scenarios for real results, red on their own assertions and then
  green; `-rxX` lists the expected failures and the unexpected passes with their reasons. The suite record reads
  "N passed, M expected to fail, K unexpectedly passing, 0 failed" (pytest's `passed`, `xfailed`, `xpassed`).
  A scenario row that the summary shows as `xpassed` is added to `tests/passing_before_their_slice.txt` (one node id a
  line), which keeps it running as an ordinary test; its line is removed when its slice lands, which the suite then
  demands (an id whose slice is built, or that no collected test has, stops the run).
- `make image` builds kb's image from the checkout (`shopsystem-kb:dev`); `make image-check` builds its own and checks
  it serves a store beside its callers in a throwaway compose project (`docker/image_check.py`), leaving nothing
  behind. Neither is part of `make test`; a release that fails `image-check` does not ship.
- `make coverage-map` runs the whole suite once under coverage of `src/kb`, in parallel, one context per test
  (`pytest-cov`, `--cov-context=test`), and writes `.coverage-map` and `.coverage-map.passed` (the passing tests;
  both git-ignored). It takes about 80 s (against 25 s for `make test`) and is not part of `make test`. Tests that
  start another program (the installed `kb`, `at_once.InAnotherProgram`, `tests/serving.py`'s programs) are not
  traced; the in-process ones, the operator's commands among them, are. `make coverage-ask ARGS="..."`
  (`tools/coverage_map.py`) answers from it, in plain text, and refuses a map missing or older than `src/kb`,
  `tests/` or `features/` ("run make coverage-map"), and a target that is not a file under `src/kb` or a line that
  is not a statement inside a function: `ARGS="tests-for src/kb/examining.py"` (or `src/kb/draft.py:127`, or
  `kb.draft.Draft.waited`) names the passing tests that execute a file, a line or a function; `ARGS="unexecuted"`
  gives, per file, the lines inside functions no passing test executes, as ranges with a count, and a total for all. A module's own
  top level runs at import, before any test, and is not asked after.
- Behaviour comes from `features/`; code is written red-green against a
  scenario, one at a time, and never adds behaviour no scenario asks for.
- A refactor is an enabling slice: its check is the suite still green and
  the structural target met.
